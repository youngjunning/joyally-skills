# 每轮自动蒸馏

自动蒸馏是本轮收尾时的内容处理，不是后台任务。只审阅本轮新增、纠正和用户明确指定的材料。

## 处理

1. 列出本轮门禁命中的原始依据，不用 Agent 的任务总结代替用户表达。
2. 按“个人记录、做事方式、文章、百宝箱、关注主题”分流。同一内容可以属于多个栏目，但只保存一个内容身份。
3. 区分可核对事实、用户明确表达和 Agent 归纳；保留必要的来源、时间、不确定性与适用边界。
4. 读取 `workbench/data/twin.json` 查找等价内容。等价内容跳过；新依据补全原内容；真正的新增才创建新片段。
5. 将待写入内容保存为临时 JSON，格式为 `{"title":"...","body":"...","sections":["memory"]}` 或同类对象数组；栏目 ID 只能使用 `memory`、`practice`、`articles`、`treasure`、`topics`。
6. 运行 `node <skill-root>/workbench/scripts/store-distillation.mjs --input <temporary-json>`，回读输出与 `workbench/data/twin.json`。只有写入和回读成功才计为新增或更新。

## 边界

- 不扫描历史会话、本机文件或其他项目来“补全”用户。
- 一次提及不足以推断长期关注；一次顺利交付不足以推断稳定能力。
- 求职、薪资、家庭、健康、凭据和其他敏感材料默认不自动写入；用户明确要求保留时，仍只写入必要摘要。
- 本地数据只服务于当前数字分身。不发布、不部署、不跨站同步。

## 收尾

把本轮实际结果交给宿主的统一收尾 Report；只有宿主没有统一 Report 时，才在最终回复末尾单独用一行报告：

- 新建内容身份：`蒸馏：新增 N`
- 实质补全已有内容：`蒸馏：更新 N`
- 全部等价或不合格：`蒸馏：无新增`
- 写入或回读失败：`蒸馏：失败（说明实际阶段）`

统计是本轮实际变更的内容身份，不是命中条件数、文件数或 Skill 加载次数。
