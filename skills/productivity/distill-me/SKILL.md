# Distill Me

把一次讨论、零散笔记或资料先整理成用户自己看得懂的本地草稿。它是一个轻量、本地优先的数字分身起点：提供与硅基紫升一致的首页结构和主题机制，但不要求用户建立托管站、数据库或固定栏目，也不会扫描历史记录、同步到其他位置或替用户发布。

## 快速开始

1. 进入 `workbench/`，运行一次 `npm install`；随后运行 `npm run open`，浏览器会自动打开本地数字分身。工作台使用 Next.js 与 React，需要由本地命令启动，无需部署或服务端账号。
2. 粘贴本次材料，保留需要的预设栏目，删除或改名不需要的栏目。
3. 点击“复制给 Agent 的请求”，粘贴到千问办公、Codex 或任意已安装本 Skill 的宿主。
4. 结果先作为草稿保存到浏览器本地；需要备份时导出 JSON。只有用户明确给出目标文件和写入授权时，Agent 才可代为保存。

预设栏目是“重要判断、关键进展、资料收藏、待跟进、文章草稿”，用于降低第一次使用的门槛；它们不是固定 schema，也不要求全部使用。“文章草稿”只沉淀选题、角度、提纲和证据，默认不发布。新增的任何栏目都应写清标题、内容和出处或上下文。

工作台首页的身份区、开始路径、成长近况、内容分区、草稿阅读区和底部主题入口与硅基紫升保持同一套信息结构；公开版只精选“重要判断、关键进展、资料收藏、待跟进、文章草稿”5 个栏目。前端统一使用 Next.js 16、React 19 与 Radix UI，不混用多套组件库。

工作台可随时切换“青山湖”“西湖”“马尔代夫”三套完整主题：树列与雾白、长堤与湖面、环礁与白沙分别重组页面的构图、表面和控件几何，而不是单纯换色。主题偏好仅保存在本机浏览器，不会影响草稿数据或导出的 JSON。

## 与 Agent 协作

把工作台生成的请求连同原始材料交给 Agent。Agent 应当：

1. 按用户启用的栏目整理，保留不确定性和来源；不把 Agent 建议写成用户事实。
2. 先返回草稿，除非用户明确要求保存到一个指定位置。
3. 写入前读取该位置的现有格式和约定，完成去重、最小改动与回读；没有写入授权或无法访问目标时，只交付草稿和缺项。

本地工作台不会调用模型、上传材料或读取用户文件。浏览器数据仅用于继续编辑，导出文件由用户自行保管。若浏览器禁止本地存储，仍可编辑、复制请求和导出 JSON。

## 边界

不要把草稿、浏览器本地保存、下载文件或 Agent 的文字回复称作已入库、已发布或已同步。涉及敏感材料时，先做脱敏或仅保留用户明确允许的摘要；不要求用户在聊天中提供凭据。
