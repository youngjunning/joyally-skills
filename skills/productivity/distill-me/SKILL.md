# Distill Me

把用户平时就在使用的 Agent 变成数字分身的持续入口。主路径是每轮主任务完成后自动检查本轮新增内容，只在轻量门禁命中时蒸馏并写入本地数据；用户指定材料时也可手动处理。不扫描历史记录、不后台监听、不云端同步，也不替用户发布。

## 安装与初始化

把 Skill 安装到用户级全局目录 `~/.agents/skills/distill-me`。千问办公通过 `~/.qwenworkcn/skills -> ~/.agents/skills` 的兼容软链接共享同一份安装：链接不存在时创建，已有正确链接时保留，已有冲突实体时不覆盖并报告。安装时读取 [宿主接入说明](references/host-integration.md)，把每轮自动蒸馏区块写入当前 Agent 确实会读取的用户级 `AGENTS.md` 或等价长期指令。修改前备份，保留其他已有指令；写入安装后的 Skill 绝对路径，并按说明回读验收。只有 Skill、兼容入口和长期指令都验收通过，才能报告“自动蒸馏已启用”；宿主没有等价入口时，报告“Skill 已安装、自动蒸馏未启用”，保留手动调用能力。

初始化本地工作台时：

1. 进入 `workbench/`，运行一次 `npm install`；随后运行 `npm run open`，浏览器会自动打开本地数字分身。
2. 确认 `workbench/data/twin.json` 可写，并回报 Skill 安装位置、长期指令位置及其回读结果、本地数据位置和工作台地址。

## 每轮自动蒸馏

当长期指令在最终回复前调用本 Skill 时，先读 [轻量门禁](references/automatic-gate.md)。未命中时不加载完整处理流程，保留“蒸馏：无新增”作为本轮收尾事实；命中后读 [自动蒸馏协议](references/automatic-distillation.md)，只处理本轮增量。宿主已有统一收尾 Report 时，将该事实交给 Report 汇总，不另加第二段结尾；自动模式不依赖 Stop Hook 或可见提示注入。

默认提供 5 个核心栏目，它们来自成熟数字分身的真实内容结构：

- **个人记录**：经历、本人明确表达的判断，以及前后发生的变化。
- **做事方式**：反复出现的方法、能力证据、协作习惯与适用边界。
- **文章**：值得系统表达的选题、观点、结构、证据与待确认部分。
- **百宝箱**：资料名称、来源、摘要、用途与再次取用的场景。
- **关注主题**：长期兴趣、核心问题，以及它们与经历、文章和收藏之间的关联。

这 5 个栏目共同回答“我是谁、我如何做事、我如何表达、我积累了什么、我长期关注什么”。一次材料可以进入一个或多个栏目，不要求每轮全部使用。

工作台首页用“认识你、理解你、看见你的方向”的路径呈现数字分身，并围绕 5 个核心栏目完成材料录入、本地片段、Agent 交接与数据导出。前端使用 Next.js 16、React 19 与内置 Lucian 组件，图标统一使用 Lucide。

工作台可随时切换“青山湖”“西湖”“马尔代夫”三套完整主题：树列与雾白、长堤与湖面、环礁与白沙分别重组页面的构图、表面和控件几何，而不是单纯换色。主题偏好仅保存在本机浏览器，不会影响草稿数据或导出的 JSON。

## 手动整理

用户给出指定材料时，Agent 应当：

1. 按用户选择的栏目整理；区分事实、用户明确表达和 Agent 归纳，保留来源、不确定性与适用边界。
2. 先返回草稿；用户明确要求“留在我的分身里”或已通过初始化授权自动写入时，再按自动协议写入本地数据。
3. 写入前读取该位置的现有格式和约定，完成去重、最小改动与回读；没有写入授权或无法访问目标时，只交付草稿和缺项。

本地工作台不会调用模型或上传材料。自动蒸馏结果保存在 `workbench/data/twin.json`，工作台读取同一份本地数据，用于查看、补充、删除和导出。自动蒸馏不扫描全部历史，不是后台监听或云端同步。

## 边界

本地写入不等于发布、对外同步或进入其他系统。涉及敏感材料时，先做脱敏或仅保留用户明确允许的摘要；写入其他位置、发布或传播继续需要相应授权。
