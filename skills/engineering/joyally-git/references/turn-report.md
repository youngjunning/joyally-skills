# Git 收尾结果契约

`joyally-git` 独立核验并输出仓库、Git 和交付事实；调用方将核验结果交给 Report 放入独立的收尾区。

## 每仓库事实

每个实际工作的 Git 仓库提供一组可独立核对的事实：项目名、当前分支、工作区、本任务 commit、push，以及适用的验证和交付门槛。使用普通文本值，不附加最终 Markdown 标题、引用块、反引号或强调样式；Report 决定这些事实在收尾区的排列和视觉层级。

1. 先写仓库显示名和当前分支。detached HEAD 显示短 SHA 和“未关联分支”，不冒充某个起始或上游分支。
2. 分别写本任务的工作区、commit 和 push 状态。commit 成功后显示本任务短 SHA；push 成功只在回读目标 ref 包含该 commit 后报告。本任务创建过临时 worktree 或本地分支时，同时写清理结果；若保留，给出精确路径、分支和原因。
3. 再按实际需要写测试、构建、制品、部署、分发或真实业务验收。这些门槛互不代替，没有证据的后续门槛写“未执行”或“未验证”。
4. 无关已有改动只说明它们影响了哪个交付决定，不计入本任务结果。多仓库分别输出，不把单仓库成功推广为全部完成。

没有 Git 仓库或本轮是纯只读任务时不制造仓库事实。本契约只负责领域事实，不负责最终报告标题、列表样式、其他 Skills 状态或蒸馏结果。
