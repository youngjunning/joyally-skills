# Joyally Browser Extension Dev

把扩展做成 Agent 的可靠执行环境，不把一次页面观察固化成业务流程。目标是同一套机制能承受按钮文案、空格、控件层级和页面阶段变化，同时把不可逆操作限制在可验证的边界内。

## 先画清调用链

进入项目后先读项目规则，再从 `manifest.json` 的后台入口和 content scripts 追踪实际加载文件。只以当前加载路径为准，不因测试、旧 Host 或历史文件仍存在就推断它们仍在线。

修改前把相关逻辑归入以下五层；一个条件无法明确归层，通常就是边界问题。

| 层 | 应承担 | 不应承担 |
| --- | --- | --- |
| Agent runtime | 模型循环、通用浏览器工具、超时、中止、并发、日志、上下文压缩 | 业务按钮名、固定页面步骤、自动选择业务分支、业务重试次数 |
| 通用页面观察与驱动 | DOM/ARIA 事实、通用引用生命周期、遮挡、滚动状态和与站点无关的导航机制 | 官网域名、项目选择器、业务字段、业务文案或某个站点的 frame 结构 |
| 项目宿主 Adapter | 官网域名与标签页绑定、跨 frame 编排、项目专用合成引用、凭据隔离和宿主权限 | 把单个项目的特例反向扩进通用 runtime，或代替 Skill 选择业务路径 |
| 业务 Skill | 页面语义、同义文案、流程分支、选择何种工具、何时停止或回查 | 绕过工具直接拼装敏感接口请求，或把模型叙述当成功凭证 |
| 受保护工具 | 结构校验、对象唯一性、权限/费用门禁、幂等、有限写入、独立回查 | 代替 Agent 决定何时采用这条业务路径，或接受模型自由拼装的关键业务参数 |

安全与机制约束不属于业务越权。官网域名限制、标签页绑定和敏感输入隔离放在项目宿主 Adapter 或受保护工具；通用引用、单任务并发、超时和中止留在 runtime；接口结构校验和写后回查留在受保护工具。

## 保持通用层宿主无关

通用包的接口与实现必须能在不认识目标站点的前提下工作。DOM/ARIA 快照、点击、填写、选择、滚动、引用失效、取消信号和同标签导航可以下沉；域名、页面路径、站点选择器、业务字段、业务文案、凭据来源和结果判定留在项目宿主 Adapter、业务 Skill 或受保护工具。

用替换测试判断归层：把项目名、域名和业务名词全部替换成另一个站点，行为与安全不变量仍成立，才是通用能力候选；替换后需要知道对象是航班、订单、乘客、座位或其他业务实体，就不是 runtime 的职责。只有一个宿主需要的编排先留在该宿主；第二个宿主出现相同需求后，再抽取宿主无关的公共 Adapter，不为假想复用扩大通用接口。

通用包的源码、文档和测试夹具都使用中性示例，例如 `example.com`、record、task、dialog 和 scrollable region。发生过业务泄漏时增加包边界负向回归，扫描项目域名、品牌名和核心业务词；负向回归保护的是层级边界，不能替代通用能力的行为测试。发布前同时核对包源码、生成物与宿主 Adapter：通用包不含项目语义，宿主仍完整承担域名、权限和业务安全约束。

## 避免脚本写死业务语义

页面观察层提供事实，Skill 解释事实。例如弹框正文为空时，快照可以补充“正文为空、存在取消和确认类按钮”；它不点击按钮，也不直接调用取消接口。按钮显示“确认”“确 认”“确定”“确 定”时，保留真实可见文字和上下文，由 Agent 按 Skill 判断。

若原站控件缺少可访问语义，由项目宿主 Adapter 补充最小结构事实。例如可以暴露“某业务记录的目标字段当前文字为 X，对应一个可见操作元素”，不要在通用包中合成项目专用控件。点击前只校验同一元素、同一记录和同一可见文字仍未变化，不校验文字必须等于某个业务词。

不要把硬编码从 runtime 挪到 DOM 快照、驱动器或测试夹具。重点搜索以下信号：

```bash
rg -n "确认|确定|选座|取消|提交|最多.*次|重复.*禁止|自动.*点击|setQuery|prepare.*submission" extension agent
```

逐项判断它是原始证据、Skill 指令、受保护工具门禁，还是代码在替 Agent 作业务决策。删除已不可达的专用业务动作，避免以后被误接回工具列表。

## 设计受保护工具

高风险或难以通过页面可靠完成的能力封装成窄工具。优先让工具从当前获准任务上下文取关键参数，模型只决定是否调用，不传证件、订单号、金额或目标对象等可被改写的业务字段。

工具在一次调用内完成：

1. 校验官网域名、会话和必填字段。
2. 查询并确认唯一目标对象。
3. 校验费用、状态、身份和对象一致性。
4. 最多执行一次不可逆写入。
5. 独立回查最终状态。
6. 返回结构化结果，如 `success`、`already_cleared`、`blocked`、`unknown`，并给出可公开的原因。

是否调用、何时从页面流程切换到工具、结果不明后是否继续观察，写在业务 Skill。运行器不另加“本轮最多调用一次”等业务策略；幂等和防重由工具的查询、写入与回查协议保证，Skill 同时给出符合风险的停止条件。

## 成功与安全

页面工具成功、HTTP 200、按钮消失、弹框关闭和模型说“成功”都不是业务成功。项目级结果校验器可以核对本次新反馈、目标对象和接口回查，但应与通用 Agent runtime 分开；它只判结果，不决定下一步动作。

通用 runtime 可以限制总模型步数和单次请求时间，但不要按页面阶段限制“只能点击一次”“同一动作三次即停止”等业务行为。高风险最终写入的次数由受保护工具或 Skill 的明确停止条件控制。

## 回归测试

每次边界改动至少覆盖：

1. 语义变体：同一动作的空格、同义词和嵌套元素变化，例如“确认／确 认／确定／确 定”。
2. Agent 自主性：runtime 不自动设置日期、提交查询、调用业务接口或限制业务动作次数。
3. 观察中立性：快照暴露真实文字和上下文，不生成写死的业务动作名称；结构证据不是可点击的合成控件。
4. 工具安全性：错误域名、缺字段、多对象、费用不符、状态不明均不写；成功必须写后回查。
5. 引用安全性：页面、行文字、元素或标签页变化后旧引用失效。
6. 生命周期：Service Worker 重载、停止、超时和迟到结果不会覆盖新任务。
7. 包边界：通用包的源码、文档、生成物和测试夹具不包含项目域名、品牌名、业务选择器或核心业务词；项目宿主仍覆盖这些约束。

测试要证明行为，不只匹配说明文字。若一条专用业务动作已删除，可增加源码级负断言防止它重新进入扩展驱动或工具列表。

## 交付

按项目脚本运行相关测试、完整扩展测试、Skill 校验和 MV3 打包。DOM 快照来自依赖包时先执行项目规定的生成同步并核对产物一致。除非用户当轮明确要求，不自行升扩展版本。安装端同步前先确认没有进行中的真实任务；源码、包、已安装扩展和本机配套运行时分别回读，且把真实业务结果与构建通过分开报告。
