# Joyally Stop

完成与 `joyally-send` 相同的工程闭环，但终点是“当前工作区已经实现并验证”，而不是 Git 或外部交付。它适合用户要 Codex 把工作做完、同时明确保留提交和推送决定的场景。

先读取并执行 [joyally-send](../joyally-send/SKILL.md) 的事实确认、最小实现、直接证明和 Joyally Loop；本文件的停止边界优先。

## 停止边界

1. 不创建 commit，不 push，不创建 PR，也不触发部署、发布或其他以 Git 交付为前提的外部动作。
2. 不因为最终不交付而降低实现、测试或独立复审标准。
3. 保留本任务修改和用户已有并行改动，不清理、不还原、不 stash 用户工作。
4. 若验证本身需要写入外部系统或产生高影响副作用，仍按原任务授权判断；本技能不补充该授权。

最终回读当前工作区，只报告本任务文件、验证结果、Joyally Loop 结论、未执行的 Git/外部交付，以及用户继续交付时需要采用的明确入口。未提交是本模式的成功终态，不是未完成。
