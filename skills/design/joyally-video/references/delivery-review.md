# 成片视听验收

用于短样组合验收、音频故障与最终导出。记录用户实际打开／下载的那一版，而非近似预览。

## 证据层次

| 层次 | 足够支持的结论 | 不能推出 |
| --- | --- | --- |
| 源码／素材 | 有BGM文件、声线配置、动画时间线 | 成片含音乐、声音自然、画面好看 |
| 技术检查 | 引用可解析、时序合法、布局／峰值合格 | 看得下去或音乐可听 |
| 真实导出 | 文件可解码、规格和音轨实测 | 完整人工审片通过 |
| 视听审查 | 明确审查者对某区间、设备、问题给结论 | 未审段落通过或留存提升 |
| 归档／发布 | 远端附件匹配或真实播放页可查 | 自动等于用户质量认可 |

各层记录对象hash、区间、环境、结论与缺项。区分 `measured / observed / user_confirmed / pending / rejected`；不编造听感、相似度或留存数值。

## 音频故障：成片听不见配乐

1. **核对对象。** 确认用户的文件／链接／版本，核验size、hash与生成记录，避免修了预览却让用户听旧附件。
2. **听真实输出。** 在目标播放器听说话段、停顿、转场、人物段与片尾，区分无声、很小、遮蔽或曲目不适合。不能听时先解码／测量，给样片请用户听审，不自称听见。
3. **沿链路隔离。** 比较干声、BGM、渲染混合轨与最终AAC；查入mix、trim／duration、静音、分组gain、自动化与效果是否生效。读当前runtime的lane／gain语义，查多级衰减或错误叠加，不先认定某字段有错。
4. **量化辅助。** 分段测干声／音乐电平、true peak和混合轨。总LUFS、audio stream或非零音乐WAV不证明音乐可感知；有对齐stem可比较贡献，AAC误差／残差不能冒充完美分离。
5. **同条件修样。** 保留原轨，在短样调关系：人声可懂、音乐有存在感，说话时适量让位、间隙恢复。掏空音乐的EQ或持续压住的ducking回到原因，不无限叠处理器。用同文、接近响度A/B和目标设备确认，不设通用BGM百分比。
6. **回验成片。** 查新混合轨、mux结果、字幕同步、峰值、时长与新hash。只改音频可复制已验收视频流另存版本，画面不意外重编码。先验本地，再沿原权限更新远端；旧版保留，默认入口明确。

未复现或只有指标时说明证据边界；用户“听不到”不能用配置标签或旧技术批准驳回。

## 画面与同步

按实际框架技术检查，解码最终MP4关键镜头、切点两侧、字幕、首尾、地图各尺度与来源页。连续播放看主体动作、节奏与转场，静态截图不能证明动效观感。

查叙述对象是否出现、动作是否随对应词句、阅读时间、目标手机／桌面可读性、真实影像与示意边界。字幕以实际语音对齐，ASR观测不代表无错字或人声自然。

升规格分别查逻辑画布、渲染尺寸、fps与源素材精度／采样，不把放大底图当局部细节或重复帧当60fps原始动作；保留声线、语速与冻结母版。

## 验收记录

沿用项目REVIEW、QA或清单，按本轮范围补字段，不必须新建JSON。最小记录包括：

- artifact：最终路径、hash、前版与本次改动范围。
- technical：执行命令／环境、结果、规格、实际音轨与证据位置。
- watch／listen：`pending / reviewed / rejected`，审查者、设备、区间与具体反馈。
- musicAudibility：音乐是否实际可听、哪些段落与谁确认；未审保持pending。
- archive／publication：各自状态、远端hash或平台播放页。

静音视频的listen／music标为带原因的 `not_applicable`，不为过门槛强加音轨。部分听审写区间，不升级为全片通过。

## 交付与后续

存储方式、单文件限制、受众与权限按项目及当前官方资料查，不缓存平台额度。超限用获准归档／分片方式，核验每片、整文件hash与恢复；独立音乐、reference及原始录音另核传播授权。

每期／版本给“基线、改变、确认方式、遗留问题”。标题、简介、章节、署名与合成披露准备好不等于上传或发布。

最终先给正确入口与关键缺项，再分开报告技术、视听、源码、归档与平台发布。技能数、模型大小、文件数、清晰度不充当体验改善证据。
