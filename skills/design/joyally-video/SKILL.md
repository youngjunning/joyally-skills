# Joyally Video

视频制作总入口，负责选专项、固定交接与视听门槛；不复制生成器、模型接口或渲染协议。目标是让观众看懂并愿意继续看，而非只得到一个能播放的文件。

## 进入与范围

先读项目协议、简报、审片结论与当前素材，明确本轮是新片、局部整改、音频修复还是输出规格变更，保留冻结版本与失败基线。既有否决保持 `rejected`，换模型、加技能或升规格不自动消除否决。

实施前说清实际会用的专项及用途，只读相关能力。延续预算、声线、片号、工具链和授权；缺能力时明确缺口，不伪造调用、不擅自安装或切换付费服务。单独修音轨、导字幕或改参数直接交专项，保留相关验收，不重启整片创作。

## 专项路由

按当前宿主提供的技能名调用，不依赖兄弟目录或历史别名。支持方只处理自己的边界，交回素材和证据，由本技能整合：

每次交接带目的／受众、锁定输入、允许修改范围、期望输出和验收证据；支持方发现需改变上游脚本、身份或事实时交回决定，不自行替换。

| 本轮工作 | 专项与交付 |
| --- | --- |
| 冷开场、叙事弧线、文案、事实组织 | joyally-writing：准确口播和转折，不复制参考作者文案或招牌口吻 |
| 视觉方向、构图、信息层级 | joyally-design：分层画面和美术标准；可渲染不等于审美达标 |
| 插画、地图、人物／道具或动画帧 | joyally-image：生成或绘制可复用素材，准确关系与标签由确定性层承担 |
| 人声、TTS、克隆、表演、对齐 | joyally-voice：干声、身份与表演证据；配乐不塞进人声生成器 |
| 音乐方向、创作、编曲或音乐评审 | joyally-music：音乐素材与许可；素材获取复用媒体专项 |
| HyperFrames媒体获取 | media-use：本地可渲染素材与来源；已有素材无需重新获取 |
| HyperFrames制作或重渲染 | 先读hyperframes，hyperframes-core／hyperframes-cli负责时间线、媒体接入与实际渲染 |
| HyperFrames动画、镜头或转场整改 | hyperframes-animation编排动作和相机，先查hyperframes-registry再手写命名效果；画素材仍交image |
| HyperFrames已接入的音乐／旁白混音 | hyperframes-audio：增益、淡变、让位与效果；最终音轨另验 |
| 用户指定其他制作框架 | 沿用其现有工作流，动效可复用joyally-motion；不强制迁移 |
| 从参考视频提取证据 | joyally-media：实际读到的内容／时间点；复刻或样式专项按请求匹配 |

本流程不授予子Agent、云端上传、发布或付费调用权限。独立代码复查按当前工程规则；它不能替代观众视听验收。

## 1. 先定叙事与镜头

有叙事的片段先明确“观众现在知道什么、为什么继续看、转折改变什么”，再安排镜头，不把文字稿逐段变成同一张大字卡。纯动效、静态循环或只改参数按原目的处理。

关键镜头写主体、动作、相机、信息揭示、音频cue和进入／退出状态。先解决美术素材质感，再编动作；淡入、平移和无目的缩放不能替代演示。按需读[镜头与分层交接](references/shot-development.md)。参考频道只比较实际读取的样本，不复制个人声音或固定表达，不以同工具宣称达到其水准。

## 2. 短样是质量门槛

新片或影响观看体验的整改，先做覆盖本轮风险的可播放短样；常见约15—30秒，也可按完整意义段取长短。包含所改的真实旁白、美术、动作、字幕和配乐，不用独立素材预览冒充组合验收。

在目标播放器审：问题是否成立、画面是否解释因果、文字能否读、声音是否有表演、音乐能否听见且不遮人声。记录时间点、文件hash、审查者与结论。旧短样只在本轮相关输入没变时复用。

- 用户确认通过，或已有同范围明确验收依据：扩展全片。
- 反馈未通过：只修对应短样，保留失败结论，不盲目批量生成。
- 尚未听／看：保持 `pending`，不拿测试或模型指标代替；宿主不能听时提供样片请用户听审。
- 用户明确“不停下来，直接做完”：可在现有权限内生成候选全片，未审范围仍显式记录，不宣布质量已验收。仅说“完整制作”不是跳过已知否决的授权。

只核验本轮风险：纯4K／60FPS变更查输出、布局、素材精度与同步，不重写脚本／克隆；纯混音可复用画面，核验音轨。

## 3. 扩展与修改

短样结论固定后按意义段扩展，绑定脚本、音频、字幕、镜头与素材版本。保留干声、独立BGM、混合轨及参数，实际音频决定时间线。关键转折更新视觉信息，区分有目的停留和缺少画面。

长方法说明、来源与许可放在合适的片尾／简介；画面保留必要的时代、示意性质和署名，展示时长按信息量决定。

“成片没音乐”先按[成片视听验收](references/delivery-review.md)诊断。BGM标签、WAV和总响度合格都不证明音乐进入成片或可听。只改混音且画面已验收时优先替换音轨、复制原视频流，避免无收益重渲染；另验时序、画面流、音频和新hash。

## 4. 成片才是交付对象

按[成片视听验收](references/delivery-review.md)分别核对技术、实际播放、观看质量、归档与平台发布。技术通过后仍要解码最终文件、检查转场和音轨；预览通过不能代替导出回验。

升级4K／60FPS从源工程渲染文字、矢量与动作，说明低精度底图和原视频采样边界；升规格不算观看体验改善。交付正确的成片入口、可编辑源工程、版本／hash、模型与素材许可、改善证据与缺项。

上传沿用项目权限和交付链，核对真实远端字节；私有仓库不能为上传方便改公开。Git、附件归档与平台发布分别报告。

## 5. 复盘与能力边界

每轮记录“对比哪个版本、改了什么、实际证据、仍有什么问题”。用项目已有记录承载 `planned / generated / technical_checked / pending / reviewed / rejected / archived / published`，不新增无关管理系统。

维护或首次应用前用[情景走读](references/scenario-checks.md)查专项和下一步是否正确。走读只证明流程决策；技能安装／校验也不能把仍未整改的旧片标为合格。
