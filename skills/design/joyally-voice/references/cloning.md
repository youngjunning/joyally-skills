# 声音克隆协议

## 选择路线

| 目标 | 首选路线 | 何时升级 |
| --- | --- | --- |
| 快速验证一段配音是否像本人 | 零样本 TTS，参考音频加准确转写 | 音色漂移、专名频繁或需长期栏目一致性 |
| 长期稳定的栏目配音 | 可复用 voice prompt 或经过授权的微调 | 多语言、强情绪、实时延迟提出新要求 |
| 保留原说话/演唱节奏，只换音色 | Voice Conversion / Singing Voice Conversion | 需要从文字重新编排内容时改用 TTS/SVS |
| 从歌词和音符生成歌声 | Singing Voice Synthesis | 目标是真人音色时再联合授权的音色转换 |

## 参考音频

1. 零样本参考先选 10–30 秒，单人、无伴奏、无混响、音量稳定，包含足够音素变化。
2. 参考转写逐字对应实际声音；犹豫、笑声、停顿和非语言声音按模型支持程度保留或剔除。
3. 训练集保留录音来源、采样率、设备、说话人授权和清理步骤；按句切分但不把呼吸全部抹掉。
4. 训练、验证和盲测文本分开；不要用训练句证明泛化。

## 最小实验

先生成三组短样：中性叙述、带数字与专名的困难文本、情绪或强弱变化文本。每组同时保留参考基线、候选模型和非克隆预置音色。只在三组都可接受后进入整篇或训练。

## 冻结栏目音色

零样本克隆通过短样后，把本次身份输入冻结成带版本的 voice profile；长期栏目不得在每次生成时重新挑参考音频。

1. 设定稳定 `voiceId` 和版本，例如 `history-narrator@v1`。保留母版参考音频、逐字转写及二者哈希；参考音频和可逆推出身份的 prompt 放在受控目录，不进入普通 Git 历史。
2. 模型支持可序列化 voice prompt、speaker embedding 或 conditioning latent 时，只生成一次并保存其模型专用制品与哈希。模型不支持时，每次从同一份母版和同一转写确定性重建，不换片段、不做新的清理或重采样。
3. 固定模型仓库与 revision、量化版本、运行时版本、语言、参考文本、文本规范化规则、采样参数、seed（支持时）、分段规则和后处理链。表演指令与身份 prompt 分开：需要改变情绪或语速时只改表演层。
4. 在新进程中重新加载 profile，生成中性叙述、数字专名和情绪转折三条固定回归短样。内容、身份、音质都通过后才标记为 `publishable`；仅保存文件但未回载生成时仍是 `technical-validation`。
5. 任何身份输入、模型权重或运行时升级都创建新版本并与当前基线盲听 A/B。新版本通过前继续使用旧版本，不原地覆盖栏目声音。

一致性表示同一 profile 下音色和发音保持可接受稳定，不承诺随机生成逐字节相同。长稿按自然段生成，每段复用同一 profile，并在最终音轨上复查音色漂移、专名、数字、响度和拼接声场。

## 失败定位

- 音色像但吐字差：先检查参考转写、语言标记、文本规范化和模型语言覆盖。
- 吐字清楚但不像：提高参考质量和音素覆盖，比较 voice prompt 与微调，不用过度降噪改变音色。
- 短句好、长句漂移：按自然段切分，固定采样参数，在拼接点保留呼吸与停顿。
- 歌声跑调或失去咬字：把旋律/节奏生成与音色转换拆开，检查 F0 提取、音域和辅音保护。
- 金属感、双声或水声：回到原始干声；检查分离伪影、重采样、声码器和过强降噪。

## 发布门槛

授权范围覆盖目标渠道；盲听确认不是只在已知答案下“觉得像”；困难文本通过；长期栏目已完成 voice profile 的保存、回载和回归短样；响度和真峰值符合目标平台；参考音频、prompt 和训练数据不随成品公开；成品保留 profile 版本、模型版本、参数、输入摘要与 AI 生成披露。
