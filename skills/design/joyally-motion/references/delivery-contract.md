# Motion 交付与验收契约

## 交付记录

对每个实质 Motion 任务记录以下决定；小任务可压成一段，不为模板制造文档：

| 字段 | 要回答的问题 |
| --- | --- |
| Outcome | 运动帮助用户理解、完成或感受到什么？ |
| Medium | 产品 UI、网页、视频、角色、2D/3D 场景还是游戏？ |
| States | 起点、触发、路径、终点、中断和错误状态是什么？ |
| Stack | 主 runtime 与辅助工具各解决什么能力缺口？ |
| Clock | wall clock、状态驱动、物理步进还是 seekable timeline？谁拥有时间？ |
| Fallback | reduced motion、低性能设备、资源失败和不支持环境如何保持语义？ |
| Evidence | 哪些预览、截图、帧、测试、导出或目标设备证明结果？ |

## 设计验收

1. 因果：每个显著运动都能追溯到用户输入、状态变化或叙事节拍；装饰不会抢过主任务。
2. 连续：对象的进入、退出、共享位置和层级变化不会制造错误空间关系；中断后从当前可见状态继续。
3. 节奏：主动作、次级反馈和环境运动有清晰层级；重复播放后仍不过度打扰。
4. 静帧：起点、关键姿态和终点各自构图成立，文字在运动中仍可读。
5. 语义：关闭或减少运动后，状态、顺序、错误和成功反馈仍完整可理解。

## 工程验收

1. 状态所有权：业务状态不只存在于 imperative timeline；卸载、路由和重入不会遗留监听器、帧循环或错误样式。
2. 时间一致：可寻址输出在相同输入和时间上得到同一画面；物理使用固定步长或录制后的确定数据，随机使用固定 seed。
3. 资源就绪：字体、图像、视频、模型、纹理和动画资产在需要的帧前加载；错误路径可观察且有 fallback。
4. 性能：在目标设备测量帧时间、主线程、GPU、内存和后台行为；根据实测削减 blur、filter、shadow、粒子、draw call、纹理或分辨率。没有目标设备数据时不声称“流畅”。
5. 可访问性：核对 `prefers-reduced-motion` 或平台等价设置、键盘、触控、焦点、屏幕阅读器结果和闪烁风险。
6. 生命周期：暂停、恢复、seek、resize、方向变化、页面隐藏和长时间重复播放均不会漂移或累积资源。

## 证据最小集

1. 产品 UI：至少覆盖 before、运动中关键状态、after、中断、快速重复触发和 reduced motion；在真实交互 runtime 验收。
2. 响应式网页：覆盖目标断点、滚动或手势边界、页面隐藏恢复和低性能降级；静态截图不能证明时间行为。
3. 可寻址视频：覆盖每个 scene、cut 两侧、首尾帧和重复渲染；对关键时间点做 frame snapshot，必要时与参考做逐帧或感知差异比较。
4. 角色与 authoring：保留可编辑源文件，覆盖极值姿态、参数组合、遮挡、关节和导出 runtime；播放器预览不证明源文件可继续编辑。
5. 3D、物理和粒子：覆盖目标设备、输入峰值、资源释放、固定 seed 或录制回放；短时顺滑不证明长会话稳定。

最终汇报分别说明源码、测试、预览、导出、部署和目标环境体验。任一后续门槛没有证据时，保留为待验证。
