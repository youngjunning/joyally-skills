# Joyally Motion

把运动作为界面和叙事的时间结构：先说明变化为何发生、用户应注意什么，再选择技术。Motion 应让状态、因果、层级和空间关系更易理解；表现力服务于目标，不用效果数量代替设计质量。

## 与相邻能力的边界

1. `joyally-design` 主导布局、视觉层级、交互结构、品牌与静态画面；本 Skill 主导时间编排、运动语言、动画实现和运动验收。联合任务保持一个整体主导 Skill，跨域决定回到责任方。
2. 视频制作或现有视频剪辑交给当前环境可用的视频工作流；本 Skill 提供 choreography、动画技术选择和 motion quality gate，不替代渲染、音频或发布流水线。
3. 静态插画和素材生成不因后续会动就变成 Motion 任务；先按图像流程得到可用资产，再在这里定义分层、骨骼、时间和交互。

## 工作流

### 1. 定义 Motion brief

先确定可检查的输出：媒介、画幅或 viewport、交互输入、时长或状态边界、目标设备、是否需要可编辑源文件、实时还是离线渲染、交付格式。把意图写成“对象因何变化，观看者因此理解或完成什么”，而不是“更炫”。

将任务归入一个主模式，必要时组合相邻模式：

1. 产品状态与微交互：反馈、进入退出、共享元素、列表重排、手势和导航连续性。
2. 表现型网页与数据叙事：滚动、路径、文字、图形变形、粒子和镜头层级。
3. 可寻址的代码动画或视频：每个时间点必须能稳定还原同一帧。
4. 角色与矢量资产：外部 authoring 产出由 runtime 播放或响应输入。
5. 实时 2D/3D、物理与游戏：场景、相机、碰撞、粒子和持续输入。

### 2. 建立 motion grammar

为每个变化写出起点、触发、路径、终点和中断行为。先编排主要叙事节拍，再处理局部装饰。保持空间连续性、因果一致和明确的注意力顺序；同一语义使用一致的速度感与 easing。弹性、overshoot、抖动和持续循环都需要表达理由。

用静止帧检查构图，用时间轴检查节奏。复杂场景先做低成本 animatic 或关键姿态，确认信息顺序后再进入高成本 3D、角色绑定或逐帧制作。

### 3. 选择最小技术栈

先沿用项目现有 runtime 和组件体系；只有能力缺口、可维护性或交付格式确实需要时才增加库。按输出、时间模型、交互、资产来源和团队可编辑性选择，不按流行度选型。

读取 [20 个工具的能力矩阵](references/tool-matrix.md)，逐项说明采用、候选或排除理由。普通 UI transition 优先使用现有 CSS、Web Animations 或平台原生能力；不要为单个 easing 同时引入多个 animation engine。

### 4. 明确时钟与状态所有权

实时 UI 可以由用户输入和 wall clock 驱动；离线渲染、可拖动时间轴、截图和可复现演示必须由单一 seekable clock 驱动。暂停、跳转、后台恢复、resize、路由切换和组件卸载都要有确定行为。

数据状态是事实来源，动画是状态之间的可中断投影。避免把最终业务状态只藏在 imperative timeline 中。随机效果使用固定 seed；媒体、字体和异步资产在首帧前就绪，失败时有明确 fallback。

### 5. 实现降级与约束

为 `prefers-reduced-motion` 或平台等价设置提供语义等价路径：保留状态变化和操作反馈，缩短、淡化或移除大幅位移、镜头运动、闪烁和无休止循环。键盘、触控、屏幕阅读器和 reduced-motion 模式必须到达同一业务结果。

优先动画化不会引发布局重排的属性；粒子、模糊、阴影、滤镜、Canvas 和 WebGL 以目标设备实测决定数量与分辨率。页面不可见、组件离开 viewport 或用户停止交互后，停止无意义工作。

### 6. 验收真实结果

按 [交付与验收契约](references/delivery-contract.md) 检查关键姿态、完整时间线、中断、重复播放、reduced motion、目标尺寸和目标设备。代码检查、单帧截图、预览播放、导出文件和线上体验是不同证据，分别报告。

只有实际产物在要求的 runtime 或播放器中通过，才称 Motion 已交付。许可证、字体、模型、贴图、音频和角色资产分别核对；“开源工具”不自动授权项目素材或 SaaS 服务。
